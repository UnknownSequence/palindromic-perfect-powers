# Assumptions of the Lean formalization

This file is the trust boundary of the Lean formalization of
*Palindromic perfect powers in Human Friendly Form*
([`hff/out/palindromic_powers_hff_lean.pdf`](hff/out/palindromic_powers_hff_lean.pdf)).
It lists everything the formal proof takes as given, and where it comes from.
The Lean counterpart is [`PalindromicPowers/Assumptions.lean`](PalindromicPowers/Assumptions.lean).

## Summary

| | |
|---|---|
| Main theorem (HFF Theorem 101) | `PalindromicPowers.main_theorem (KR : KnownResults) (hg : 2 ≤ g) (hk : 2 ≤ k)` in `PalindromicPowers/Final.lean` |
| Unconditional form | `PalindromicPowers.main_theorem_unconditional` in `PalindromicPowers/MainTheorem.lean` (= `main_theorem knownResults_ofMathlib`) |
| Published hypotheses assumed | **none** |
| Known results assumed | the analytic prerequisites of the HFF, bundled as `KnownResults` (10 fields, of which the proof uses 8); all 10 are proved from Mathlib in `PalindromicPowers/Discharge.lean` |
| Project axioms | none (no `axiom`, no `sorry`, no `native_decide`; checked by `PalindromicPowers/Audit.lean`) |

So the formal content is

> **Lean + Mathlib + the HFF argument = Theorem 101**,

with the textbook facts the HFF lists as prerequisites made explicit as the
hypothesis `KnownResults`, and then discharged.

The current status of every block is in [`README.md`](README.md) (section *Status*)
and is regenerated by `lake env lean PalindromicPowers/Audit.lean`.

## 1. Published hypotheses

None. The HFF document says (paragraph *Prerequisites*): "No result from the literature is
imported, and no computer calculation is used." The references it cites play these roles:

If a later version of the argument imports a published theorem, it is to be added here and
as a field of a separate structure `PublishedResults` in `Assumptions.lean`, transcribed with
its printed hypotheses and parameter range, and passed to the main theorem as an explicit
hypothesis (never as an `axiom`).

## 2. Known results (the HFF prerequisites)

The HFF *Prerequisites* paragraph lists the background facts the proof uses. In Lean they are
handled as follows.

### 2a. Algebraic prerequisites: used directly from Lean core and Mathlib

| HFF prerequisite | Lean / Mathlib |
|---|---|
| Division with remainder | `Nat.div_add_mod`, `Nat.mod_lt`, `Int.emod_emod_of_dvd`, … |
| Congruences | `Nat.ModEq`, `Int.ModEq` |
| Greatest common divisors | `Nat.gcd`, `Int.gcd`, `Nat.Coprime` |
| `p`-adic valuations | `Nat.factorization` |
| The Chinese remainder theorem | used through `Nat.factorization_prime_le_iff_dvd` (a number divisible by every prime-power part of `n` is divisible by `n`) |
| The binomial theorem | `add_pow` |

These are not hypotheses: they are theorems of Lean/Mathlib, checked by the Lean kernel.

### 2b. Analytic prerequisites: the fields of `KnownResults`

Each analytic prerequisite is a field of the `Prop`-valued structure `KnownResults`,
stated in the form in which the HFF uses it. Every Lean lemma whose HFF proof relies on one
of them (directly, or through a cited block) takes an explicit argument `KR : KnownResults`.

| Field | Statement | HFF prerequisite | HFF proofs using it | Lean proofs using it | Proved in `Discharge.lean` from |
|---|---|---|---|---|---|

| `taylor2` | `f ∈ C²`, `a < b` ⇒ `∃ c ∈ (a,b)`, `f b = f a + f'(a)(b-a) + f''(c)(b-a)²/2` | Taylor's theorem with the Lagrange remainder | 43 | — (unused) | Rolle's theorem `exists_hasDerivAt_eq_zero` |

| `integral_inv` | `∫₁ˣ dy/y = log x` for `x ≥ 1` | `∫₁ˣ dy/y = log x` | 7, 8 | — (unused) | `integral_inv_of_pos` |
| `norm_e_sub_one` | `‖e(y) − 1‖ = 2 |sin πy|` | `|e(y)−1| = 2|sin πy|` | 6, 47 | 6, 47 | `Complex.norm_exp_I_mul_ofReal_sub_one` |
| `sin_pi_ge` | `2‖y‖ ≤ |sin πy|` | `|sin πy| ≥ 2‖y‖` | 6 | 6 | `Real.sin_add_int_mul_pi` and Jordan (`Real.mul_le_sin`) |

| `distZ_zmul_le` | `‖nx‖ ≤ |n| ‖x‖` (`n ∈ ℤ`) | property of `‖·‖` | 17 | 17 | minimality of `round` (`distZ_le_abs_sub`) |

The column "Lean proofs using it" is computed by `#known_results_usage` in
`PalindromicPowers/Audit.lean` (the block's own proof, including its private auxiliary
lemmas). It agrees with the HFF except in three places, where the Lean proof took a more
elementary route: Lemma 7 uses Mathlib's `harmonic_le_one_add_log`, Lemma 8 the inequality
`1/(2m+3) ≤ ½ log((2m+3)/(2m+1))` instead of the integral, and Lemma 43 the polynomial
inequality `(a+h)^k − a^k − k a^{k−1} h ≤ ½k(k−1)(a+h)^{k−2}h²` instead of Taylor's theorem.
Lemma 76 uses the triangle inequality for `‖·‖`, which the HFF proof uses silently. So
`taylor2` and `integral_inv` are carried in the bundle (they are HFF prerequisites) but the
proof of `main_theorem` does not use them; `#used_known_results main_theorem` lists the other
eight.

`‖·‖` is the distance to the nearest integer, `distZ x = |x − round x|`, and
`e(y) = exp(2πiy)`; both are defined in `PalindromicPowers/Conventions.lean`.

### 2c. Not assumptions

* **Elementary facts about the notation of Block 1** (`e(x+y) = e(x)e(y)`, `|e(x)| = 1`,
  `‖x + n‖ = ‖x‖`, `‖x‖ ≤ 1/2`, monotonicity of `min(A, H/y)`, …) are proved in
  `PalindromicPowers/Basic.lean`. The HFF uses them silently.
* **Auxiliary lemmas** inside each section file are part of the proof of the block they serve
  (each says so in its docstring); they are `private` to that file.

## 3. What a reader has to trust

1. The Lean kernel and Mathlib.
2. That the **statement** of `main_theorem` says what Theorem 101 says. It uses only `palSet`
   (Definition 28), which uses only `digit g n i = ⌊n/gⁱ⌋ mod g` (Definition 3):
   ```lean
   theorem main_theorem (KR : KnownResults) (hg : 2 ≤ g) (hk : 2 ≤ k) :
       ∃ γ : ℝ, 0 < γ ∧ γ < 1 ∧ ∃ C' : ℝ, ∀ L : ℕ, 1 ≤ L →
         (((palSet g L).filter (fun n => ∃ x ≤ n, x ^ k = n)).card : ℝ) ≤
           C' * ((palSet g L).card : ℝ) ^ (γ / k)
   ```
   `MainTheorem.lean` also states it with Mathlib's `Nat.digits` in place of `palSet`.
3. Nothing else: the fields of `KnownResults` are proved in `Discharge.lean`, so
   `main_theorem_unconditional` has no hypotheses beyond `2 ≤ g` and `2 ≤ k`.

## 4. Lean-friendly restatements

The Lean statements are faithful to the HFF blocks, but some are phrased to suit Lean:
digits are defined by `⌊n/gⁱ⌋ mod g`; the convention `H/0 = ∞` becomes the function
`minDiv`; constants that the HFF introduces with "there is" or "we fix" (`u_*`, `c`, `C`,
`F̂_j`, `μ`, `Δ`, `t'`) are explicit definitions; the spacing lemmas carry weights; and
"`A ≪ B` for `L` large" is written `∃ C₁ L₀, ∀ L ≥ L₀, A ≤ C₁ * B`. The full list, and the
HFF version whose blocks match the Lean statements one to one, are in
[`hff/LEAN_CONVENTIONS.md`](hff/LEAN_CONVENTIONS.md) and `hff/out/palindromic_powers_hff_lean.pdf`.
